## What to ask for at the meeting

A **B2B profile with nAPI (`B2BZasilka`) access**, from the ČP sales rep.

Insist on **nAPI**, the REST/JSON interface. The older `POLService` API
authenticates with PostSignum client certificates, which would mean mounting a
`.pem` certificate and private key into the Railway container and rotating them
by hand. nAPI needs no files — three string credentials, generated by you.

## Where the credentials come from

Once the profile exists: **Služby pro firmy → Správa B2B profilu**. You generate
and can rotate all three there.

| Railway variable | ČP calls it | Shape |
| --- | --- | --- |
| `BALIKOVNA_API_URL` | — | base URL; test is `https://b2b-test.postaonline.cz:444/restservices/ZSKService/v1/` |
| `BALIKOVNA_API_TOKEN` | API klíč (token) | UUID |
| `BALIKOVNA_API_SECRET` | Tajný (privátní) klíč | base64 — signs each request |
| `BALIKOVNA_API_CUSTOMER_ID` | ID CČK | contract number |

Also worth getting in the same conversation:

- the **production** base URL (only the test one is public);
- the **YAML spec**, which is what actually documents the request-signing
  scheme — it is the one thing that cannot be inferred from outside;
- confirmation that **Balíkovna is service code `NB`** on your contract.
  Test accounts are restricted to services S / M / L / XL.

## What already works without any of this

- The provider is built and registered, keeping the identifier
  `ceska-posta-fulfillment` so the existing shipping option is not orphaned.
- Packing an order creates a real fulfilment and decrements stock.
- Because no carrier knows about the parcel, the order **stops** at
  „Čeká na ruční podání zásilky." and she confirms handover herself. The
  customer's „odesláno" e-mail only goes out at that point — never on the
  strength of a database row (A1).
- Parcel weight is summed from the products, falling back to
  `default_parcel_weight_kg` (D2). The retired Packeta provider hardcoded 2,5 kg
  for every parcel, which overpays on every small order.

## What changes once the credentials land (P4-2)

One method gains a body — the seam is marked in
`backend/src/modules/ceskaPostaFulfillment/service.ts`. `createFulfillment`
starts returning `mode: "api"` with a tracking number and a PDF label, and the
two-phase handover collapses back into a single click, because at that point the
carrier genuinely has the parcel.

Nothing else changes: the ship workflow, the card, the e-mail and the stage
machine already branch on that one flag.

**Note the deliberate belt-and-braces:** if the credentials are set but the API
call is still unimplemented, the provider falls back to record-only and logs a
warning rather than throwing. A missing integration must never be the reason she
cannot ship.
